# RTL8822BU (`88x2bu`) для Realme C51 / RMX3834

Драйвер RTL8822BU (88x2bu) для Realme C51 / RMX3834 — Android 12, kernel 5.4.254.
Сборка и работа в Termux, monitor mode, проверено с TP-Link Archer T3U / T3U Plus (2357:012e).

Собрано под **стоковое ядро этого устройства** и подписано **родным ключом Realme** из GPL-исходников. На устройстве `CONFIG_MODULE_SIG_FORCE=y`, поэтому подпись обязательна.

Ядро устройства (проверено):

```
uname -r -> 5.4.254-android12-9-ge5ca70696329-ab505
```

- `88x2bu-device.ko` — это stripped+re-signed копия `88x2bu.ko`, содержимое идентично.

## Установка (Termux + root)

```sh
# положить файлы, например:
# adb push 88x2bu-device.ko /data/local/tmp/88x2bu/
# adb push install.sh       /data/local/tmp/88x2bu/

su -c 'sh /data/local/tmp/88x2bu/install.sh /data/local/tmp/88x2bu/88x2bu-device.ko'
```

Или вручную:

```sh
su
rmmod 88x2bu 2>/dev/null
insmod /data/local/tmp/88x2bu/88x2bu-device.ko
dmesg | tail -40
ip link
```

Ожидаемо: в dmesg `usbcore: registered new interface driver rtl88x2bu`, в `ip link` появляется `wlan1` (или `wlan0`, если встроенный Wi-Fi не занял имя).

## Проверка

```sh
su -c 'iw dev'
su -c 'iw phy | grep -i -A2 monitor'
su -c 'ip link set wlan1 up'
su -c 'iw dev wlan1 info'
```

Monitor mode:

```sh
su -c 'ip link set wlan1 down'
su -c 'iw dev wlan1 set type monitor'
su -c 'ip link set wlan1 up'
su -c 'iw dev wlan1 info'      # type monitor
```

## airgeddon

Интерфейс обычно определяется сам; если нет — укажи `wlan1` вручную.

**Про инжект:** RTL8822BU держит monitor mode, но инжект частичный/нестабильный. Для пассивного сбора handshake/PMKID этого достаточно. Для deauth и активного инжекта надёжнее **RTL8812AU / RTL8814AU / AR9271** (Alfa AWUS036ACH / AWUS036NHA).

## Если не грузится — dmesg

| сообщение | причина / что делать |
|---|---|
| `version magic '...' should be '5.4.254-android12-9-ge5ca70696329-ab505 ...'` | взят не тот файл; нужен `88x2bu-device.ko` |
| `disagrees about version of symbol` | CRC не совпали (ядро собрано с другим конфигом); пришли строки из dmesg |
| `module verification failed` / `Key was rejected` | подпись не та (не должно случиться: ключ Realme) |
| `Unknown symbol ...` | не хватает зависимости в ядре (cfg80211/mac80211 в стоке `=y`) |
| `File exists` | `rmmod 88x2bu` перед `insmod` |

Пришли `uname -r` и `dmesg | grep -iE '88x2bu|version magic|disagrees|Unknown symbol'` — по ним видно, что дальше.

## Автозагрузка (Magisk, опционально)

```
/data/adb/modules/88x2bu/
├── module.prop
├── 88x2bu-device.ko
└── post-fs-data.sh
```

`module.prop`:
```
id=88x2bu
name=RTL8822BU driver (RMX3834)
version=5.13.1
versionCode=1
author=outcome
description=Signed rtl88x2bu for Realme C51 stock kernel 5.4.254
```

`post-fs-data.sh`:
```sh
#!/system/bin/sh
MODDIR=${0%/*}
insmod "$MODDIR/88x2bu-device.ko"
```

## Как собрано

- Исходники ядра: `realme-kernel-opensource/realme_C51_C53_Note50_C60_C51_N53-AndroidU-kernel-source` (`master`, 5.4.254).
- Дефконфиг: `NTeditor/rmx3834-kernel-docker/rmx3834_defconfig`.
- Toolchain: `clang-r416183b` (android-12.0.0_r0.16), `aarch64-linux-gnu-`, `LLVM=1`.
- Драйвер: `morrownr/88x2bu-20210702` (`v5.13.1-20-gbd7c7eb9d`).
- Ключ подписи: `certs/signing_key.pem` из дерева Realme.
- Правки: autofix локальных angle-include; `CONFIG_UAPI_HEADER_TEST` off; для модуля `KCFLAGS="-Wno-error -Wno-error=unknown-warning-option -Wno-unknown-warning-option"`; `utsrelease.h` вручную выставлен на полный release устройства (внешний `make M=...` его не перегенерирует).
- Build-каталог: `/home/mmm/rmx3834-build/` (`build2.sh`, `Dockerfile`).
